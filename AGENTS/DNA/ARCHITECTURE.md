## Runtime topology

Four execution contexts, each with a distinct job:

| Context | File | Lifetime | Does |
|---|---|---|---|
| Service worker | `background.ts` | ephemeral, event-driven | toolbar click and keyboard command, badge, `chrome.tabCapture.getMediaStreamId` (must happen inside the click), opens/focuses the app tab, forwards nothing else |
| App tab | `app/app.ts` | while open; pinned; warns on close when busy | owns the recorder, the audio graph, OPFS writes, transcription workers, export, settings UI, library UI |
| Content script | `content/meet.ts` | per Meet page | observes the DOM, emits speaker events and roster to the extension via `chrome.runtime.sendMessage`; mirrors every message as a `rescribe:event` CustomEvent on `window` for the e2e harness (Meet's scripts cannot read the detail across worlds) |
| Storage worker | `workers/storage.ts` | per recording | appends video chunks and PCM blocks to OPFS through one sync access handle per file, flushing after every write; one queue keeps arrival order |
| Transcribe worker **(planned)** | `workers/transcribe.ts` | per job | VAD, then parakeet.js on WASM (default) or WebGPU, one channel per job |

Messages that cross `chrome.runtime` (service worker, app tab, content scripts) are typed in `src/lib/messages.ts`; the union there is the single roster of those message types. A worker's `postMessage` protocol is typed in the worker's own file and imported by its one client, so adding a worker touches no shared file.

## Data model (`src/lib/types.ts`)

- `ChannelId`: `'mic' | 'display'`. Two channels, always. A recording may have only one of them.
- `Source`: what a channel captured (`microphone`, `tab`, `window`, `screen`) plus a label (tab title, device name).
- `Recording`: id (UUID), `startedAt`/`endedAt` (epoch ms, the only wall-clock values in the model), title, sources, status (`recording → recorded → transcribing → done | failed`), container, export path, `error` (why it failed, or why it is `recorded` without an export path), `note` (non-failure information, e.g. recovered after an interruption).
- `Segment`: `{ channel, start, end, text, words? }`, seconds from recording start. Output of the ASR engine, per channel.
- `SpeakerInterval`: `{ channel, speaker, start, end, source }` with `source` one of `platform | model | channel`. The unit of speaker evidence. Adapters, the diarizer and channel identity all produce these.
- `LabelledSegment`: a `Segment` plus `speaker` and the `evidence` that decided it.
- `Turn`: consecutive labelled segments by the same speaker, merged for rendering.
- `Settings`: folder handle id, path template, my name, container, mic default, model choice.

## Clock

Recording-relative seconds everywhere in `lib/`. `startedAt` is the epoch ms of the first captured sample, defined precisely as: `Date.now()` taken in the app tab in the same task that creates both AudioWorklet taps (`Recorder.start`, after the AudioContexts are running). Both taps begin at the next render quantum, within ~10 ms. From then on each tap writes exactly one sample per 1/16000 s of context time, zeros when its input is absent, so `sample_index / 16000` in either PCM file is recording-relative seconds from `startedAt`. The MediaRecorder starts in the same task; its video may begin a frame later, which is playback, not pipeline timing. Content scripts stamp with `Date.now()`; the app tab converts on receipt. See [[INVARIANTS]].

## Storage

- **OPFS**, per recording directory `recordings/<id>/`: `video.mp4` or `video.webm` (MediaRecorder chunks appended), `mic.pcm` and `display.pcm` (16 kHz mono Int16 little-endian, raw, no header; each present only when that channel had an audio track; appended by the AudioWorklet taps via the storage worker), `events.jsonl` (created empty at start; `Recorder.appendEvent` appends one JSON line; the speaker-event consumer lands with #3). All four are opened, truncated and written only by the storage worker during the recording.
- **IndexedDB** `rescribe`: `recordings` (the `Recording` records, keyed by id), `handles` (the export directory handle under key `export`).
- **chrome.storage.local**: `Settings` minus the handle.
- **Export folder** (user's disk): `<template>/recording.mp4|webm` written on stop, streamed from the OPFS file; `transcript.md`, `transcript.json`, `meta.json` on transcription completion (#2). `<template>` comes from `lib/pathtemplate.ts` (`/` nests directories) and the last segment gets ` (2)`, ` (3)`… when it already exists. `Recording.exportPath` is that relative path; the recording stays `recorded` with `exportPath` unset and `error` set when the export fails (no folder chosen, permission not granted), so a re-export can retry.
- **Storage client** (`storage/store.ts`, `storage/export.ts`), what transcription and the library call: `listRecordings`, `getRecording`, `putRecording`, `updateRecording(id, patch)`, `getVideoFile(id, container)`, `getChannelFile(id, channel)` (a `File` to slice), `readChannelPcm(id, channel)` (the whole channel as `Int16Array`) + `pcmToFloat32`, `deleteMedia(id)` (OPFS only), `deleteRecording(id)`; `getExportRoot`/`setExportRoot`, `ensureExportPermission()` (call inside a user gesture), `getExportDirectory(rec, template)` (creates or reopens `<template>/`), `writeExportFile(dir, name, data)` (Blob, bytes, string or stream).

## Pipeline

Steps 1–2 are built; 3–5 are **(planned)**.

1. Capture: streams → two `AudioContext`s (`recorder/graph.ts`): the 16 kHz tap context with one `AudioWorkletNode` tap per channel → 200 ms Int16 blocks → storage worker; the mix context with every channel → `MediaStreamAudioDestinationNode` → `MediaRecorder` (1 s timeslice, a keyframe per timeslice) with the video track → storage worker. Tab capture also plays the display channel through the mix context's speakers, since Chrome mutes a captured tab for the human.
2. Stop: MediaRecorder stop → last chunk written → taps flushed → storage worker closes the files → `endedAt` → `finalize`: export the video into `<template>/`, mark `recorded`. A record found at `recording` on app start (tab closed, browser crashed) is finalized from what reached disk (`recoverInterrupted`), `endedAt` from the PCM length, or marked `failed` when no video reached disk.
3. Transcribe: per channel, VAD → voiced regions → Parakeet → `Segment[]` with region offsets applied.
4. Attribute: `SpeakerInterval[]` from channel identity + platform events (+ model) → `attribute()` → `LabelledSegment[]`.
5. Render: `toTurns()` → `transcript.md`, `transcript.json`; export; mark `done`.

Each stage is a function over data on disk, so any stage can be re-run from the library.
