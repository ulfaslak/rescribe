# Development

## Setup

```
npm install
npm run build          # src/ → dist/
```

Load `dist/` once in the human's browser (Brave): `brave://extensions` → Developer mode → Load unpacked. Chrome keeps pointing at that folder; after every build, click the reload icon on the Rescribe card (or `⌘R` on the app tab is not enough, the service worker and content scripts need the extension reload).

`npm run watch` rebuilds on change. You still reload the extension by hand.

## Commands

| Command                           | What                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run check`                   | `tsc --noEmit`, strict. Must be clean.                                                                                                                                                                                                                                                                                                                                                |
| `npm test`                        | Node's test runner over `src/**/*.test.ts`. Runs TypeScript directly (Node 25 type stripping), which is why source imports use the `.ts` extension, and why `src/lib/` uses no TypeScript-only _runtime_ syntax: no parameter properties, no `enum`, no `namespace`, no `import x = require()`. A file that uses them fails to load in `npm test` while `tsc` and esbuild stay green. |
| `npm run e2e`                     | Builds, then Playwright drives the real extension in Chromium. | `npm run format` / `format:check` | Prettier. A PostToolUse hook runs `--check` on files you edit.                                                                                                                                                                                                                                                                                                                        |

## The e2e harness (`e2e/`)

`e2e/fixtures.ts` launches a persistent Chromium context with the extension loaded from `.playwright/extension/`, a copy of `dist/` made per launch whose manifest adds `host_permissions: <all_urls>` (the stand-in for the real click's `activeTab` grant, which the start dialog's overlay is injected on; it reaches the file:// capture target too, so a test that wants the fallback window clicks on a `chrome://` tab), and Chrome's fake-media flags:

- `--use-fake-device-for-media-stream` + `--use-file-for-fake-audio-capture=<wav>`: the microphone is a WAV file (`e2e/fixtures/speech.wav`, generated by `scripts/make-fixtures.sh` with macOS `say`).
- `--use-fake-ui-for-media-stream`: permission prompts auto-accept.
- `--auto-select-tab-capture-source-by-title=<title>`: `getDisplayMedia` picks the tab with that title without a picker.
- `--autoplay-policy=no-user-gesture-required`: a target tab can play a tone so tab-audio capture is measurable.

The profile lives in `.playwright/profile/` (gitignored) and is **reused between runs on purpose**: the Parakeet model (about 650 MB for the default int8 WASM variant; another 2.4 GB if the WebGPU variant ran) is cached in its IndexedDB, so only the first run downloads it. Don't delete the profile to "clean up". The fixture does delete the profile's `Service Worker/` directory before each launch, because Chromium would otherwise run the previous build's `background.js` (see [[ENVIRONMENT_NOTES]]). `PW_PROFILE=<dir>` uses another profile.

Headless by default (`channel: 'chromium'`, new headless supports extensions and, on this Mac, WebGPU with f16). `HEADED=1 npm run e2e` opens a window; `CHROME_CHANNEL=chrome` uses the installed Google Chrome instead of Playwright's Chromium; `RESCRIBE_E2E_WEBGPU=1` also runs the WebGPU transcription variant (2.4 GB download, skipped by default).

Extension pages are opened by URL: `chrome-extension://<id>/app/app.html`, where the id comes from the service worker URL (see `fixtures.ts`). The id of an unpacked extension is a hash of its path (`.playwright/extension/` in the checkout), and the model cache lives in the extension origin's IndexedDB, so **each worktree's first e2e run downloads the model again** into that worktree's profile.

`e2e/helpers.ts` holds the app-page helpers for specs written after `record.spec.ts` (open the page, seed the export folder, record, poll a record until a status, read OPFS files). `record.spec.ts` covers steps 1–2 and sets `autoTranscribe: false` in its `openApp`, so a recording ends at `recorded` with the pill idle; `pipeline.spec.ts` sets it back. Settings persist in the profile between tests, so a spec that depends on one sets it explicitly.

## Self-testing: pick the method that produces signal

- **Pure logic** (`src/lib/`): unit tests. Write the failing case first when fixing a bug.
- **The record-to-transcript path**: an e2e run. Assert on files (OPFS length, exported file size, ffprobe on the exported video via `ffprobe` from Homebrew), not on UI text.
- **UI glue** (settings form, library list): a Playwright walk of the app page with screenshots into `screenshots/` (gitignored).
- **Anything the fake devices cannot exercise**: real Meet behaviour, the real folder picker, QuickTime playback. Write a [[LIVE_CHECKS]] entry with trigger, steps and success criteria, and tell the human in the PR.

Negative control: for every fix, make the check fail once (revert the fix or restore the triggering input), then re-apply.

## Testing ideology

Test the logic that decides things: attribution, turn merging, VAD boundaries, clock conversion, path templates. Those are pure functions and their bugs are silent (a wrong speaker label looks like a right one). Don't test the DOM glue or Chrome APIs through mocks; test them through the real browser in e2e, or not at all. A test that can only pass by mocking the thing under test proves nothing.

## Cleanse

`/cleanse` (`.claude/skills/cleanse/`) reviews the DNA against itself and the code, sweeps the ledgers in `AGENTS/`, prunes redundant tests and closes straggler issues. Shallow reads the DNA and skims the code; deep reads every source file, checks each invariant against the test that pins it, the manifest and the storage layout against the prose, and the mistake log for patterns. Its mechanical half is a script:

```
node .claude/skills/cleanse/scan.mjs --verbose
```

Broken `[[links]]` and `§` section references, paths the docs name that are not on disk, and ARCHITECTURE's file structure against the tree exit 1. Orphan source files, quoted test titles that match no test, and ledger entries missing a field or a tag are printed to judge. Run it on its own after renaming a file, a heading or a test that the docs name.

## Release

There is no deploy. After a merge, from the primary clone:

```
git checkout main && git pull && npm run build
```

Then the human reloads the extension at `brave://extensions`. Say so in the closer of any session that merges.

## Worktrees

`git gtr new <branch>` creates `../rescribe-worktrees/<branch>/` and should run `npm install` (`.gtrconfig`; see [[ENVIRONMENT_NOTES]] if it didn't). After merging, remove the worktree **before** deleting the branch: `gh pr merge --delete-branch` cannot delete a local branch that a worktree still holds, so the order is `git gtr rm <branch>`, then `git branch -d <branch>`. Each worktree has its own `dist/`; Chrome loads the primary clone's `dist/`, so a worktree's build is only for its own e2e runs. Never load a worktree's `dist/` into the human's Chrome.
